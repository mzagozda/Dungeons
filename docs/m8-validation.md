M8 remains incomplete. Settings, accessibility and the original audio implementation have local functional evidence; listening review, remaining art/polish, reviewed visual baselines, store packaging, platform acceptance, nightly CI and soak gates remain pending.

## Persistence and runtime

`GameSettings` contains versioned video/audio/controls/accessibility preferences. `SettingsStore` limits JSON to 64 KiB/depth 16, rejects duplicate/unknown keys, invalid enum/range/collection values and unsupported versions, retains corrupt bytes in timestamped backups, then recreates defaults. Writes use a flushed temporary file and atomic replacement. Failed saves leave the previous committed snapshot active; editor dictionaries are copied rather than retained. The initial platform/device preset is saved once and existing settings survive later defaults. Fourteen store cases pass at `artifacts/m8/settings-store/mzag_R5-7600X_2026-10-26_21_51_06.trx`.

The normal app creates `SettingsRuntime` after any renderer restart and before gameplay. It applies preset/custom graphics, adaptive bounds, native canvas scale, windowed/fullscreen/VSync, remembered window geometry, five audio buses (Master plus Music/SFX/UI/Ambience), InputMap bindings, haptics, touch configuration and accessibility. Master plus four category controls resolve the wording difference between §14 and §16.4 (D22). `Alt+Enter` toggles desktop fullscreen. Application pause/close flushes settings; physical lifecycle/window restoration remains separate validation. Development `--quality` overrides remain authoritative for native probes.

Audio bus values and mute are functional and now bind the original sound/music bank described below. Reduce motion binds existing hit-stop suppression and the shared preference for later shake effects. New settings do not imply completion of those dependent systems.

## Input and touch

The same default-binding definition now feeds InputMap and the settings editor. Rebinding replaces the selected keyboard/mouse or gamepad group while preserving the other group, keeps changes in a draft until Apply, and exposes shared-binding conflicts before saving. Unapplied changes are discarded by Back. Input state clears when a committed map changes. Touch-emulated mouse events cannot become bindings. The native GUI drag uses the same hit geometry, clamping and transactional button-spacing rules as play; positions are saved in canonical right-handed safe-area coordinates and mirror on use. A layout that cannot fit a smaller safe area falls back to valid default positions, and a screen too small for the minimum layout disables touch hit testing without throwing.

Optional aim assist resolves into the recorded `PlayerInput` boundary, leaving Normal behavior unchanged. Off uses facing/raw mouse aim outside touch; touch retains normal assistance. Strong halves angular score cost and widens mouse snap to 1.8 m while keeping combat ranges, LOS, leading and manual aim. Four policy cases pass at `artifacts/m8/settings-policy/mzag_R5-7600X_2026-10-26_22_03_58.trx`, including replay verification of an explicit Off command. ## Bounded application logging

`RollingFileLogger` implements ILogger with a preallocated 256-entry ring and one bounded retry record. Enqueueing ordinary static diagnostics performs no disk IO and allocates zero bytes, even on overflow. Entries capture UTC, severity/category, level id, unsigned seed and exact simulation tick. Messages/context are capped; control characters are JSON-escaped; clipping preserves Unicode scalar boundaries. Dropped counts and interrupted-tail recovery bytes are explicit fields. Host flushing writes UTF-8 without BOM/LF JSON lines, rotates only the five owned names `dungeons.log`/`dungeons.1.log` through `.4.log`, and caps each at **1,000,000 bytes**. Manual and historical unrelated files are preserved. Complete earlier lines survive recovery of an interrupted final record. Storage errors retain the pending entry and retry later without throwing into gameplay. Closing each flush batch releases Windows readers and avoids idle handle/flush work.

`GameLog` is app-scoped and creates the sink before registry/catalogue/settings/profile work. Normal simulation receives a SessionLog retaining level/seed at construction and binding the live tick afterward; it does not format/write files inside Step. Host errors and persistence/import warnings feed the sink while preserving native console diagnostics. Startup/adapter/settings/mission lifecycle context is logged, and pause/close/exit flush pending records. Release Debug wrappers elide argument evaluation, and direct Debug records are filtered in Release. F3 shows queued/dropped records. Normal Godot file logging is explicitly disabled on every platform to avoid its separate, size-unbounded log set; native stdout/stderr still exists. QA's renderer-relaunch service now passes an explicit unique child --log-file path, and its strict parent/child evidence remains intact. The relaunch helper also normalizes a supplied relative evidence directory; the retained earlier relative-path failure is not accepted as a pass.
