# NativeAOT compatibility repair

The adopted host's iOS SDK enables `PublishAot`, `PublishAotUsingRuntimePack` and `UseNativeAOTRuntime` in its installed `iOS.props`. Desktop/Android JIT checks therefore did not establish iOS serialization compatibility. This audit found a real defect. The repair is now **active in the main workspace** after the complete isolated rendered/package checks below. The 33-file adoption is hash-verified at `artifacts/host-migration/native-aot-adoption.json`; previous source/packages remain under `pre-native-aot-20261027/`. The validated isolated workspace remains preserved at `artifacts/ios-aot-workspace/`.

## Reproduction and scope

Shipping-subset AOT/trim analysis inventories **49 distinct diagnostics**: 24 IL2026 and 25 IL3050, across six Core JSON-construction files and seven host persistence/QA files. The strict initial build fails. An explicitly diagnostic-only warning inventory then lists every location; permanent checks still treat warnings as errors. Raw logs and structured inventory are in `artifacts/host-migration/ios-aot-audit/`.

A package-free console links the actual production settings/profile code and portable Core. The corrected JIT fixture passes with JSON reflection enabled. With reflection disabled, **settings save, profile save and actual replay JSON writing fail**; the catalogue still succeeds. The first probe had an unrelated lower-case touch-position fixture key; that failed attempt is retained and corrected before drawing the compatibility conclusion. Evidence: `runtime-reflection-corrected-before/` and `runtime-reflection-disabled-before/`.

The repair uses generated `JsonTypeInfo` for settings/profiles, generic enum converters retaining the existing string-only enum policy, and explicit JSON-node construction instead of reflection-dependent generic array insertion/anonymous serialization. Core targets remain `net8.0;netstandard2.1`; no simulation algorithm, data file, schema or replay identity is changed. Six Core files change JSON construction. The earlier completed main-host soak retains its original source/payload checkpoint; the repaired package has its own new run.

## Combined-gate failures and repairs

The first combined attempt (`ios-aot-full-gate.launch/`) fails at the thumbnail CLI's Debug compilation: the shipping-subset AOT restore overwrote shared NuGet assets without test dependencies. Earlier `dotnet test --no-build` calls returned zero without executing tests or producing TRX files. Those UI/editor calls earn no validation. The checker now restores the locked Debug/editor graph in `finally` and explicitly requires `IsTestProject=true`. `Assert-TestRun.ps1` requires one actual complete passing TRX with a minimum case count, no skips and no orphan/native-leak diagnostics; every Godot suite in the candidate cascading runner uses it. Actual empty-directory, zero-execution and orphan-warning reports are rejected. PowerShell's XML adapter required reading `DocumentElement.InnerText`; reading the document's own `InnerText` missed the warning and was corrected against the preserved report.

The second attempt (`ios-aot-restored-debug-full-gate.launch/`) fails after its second full-clear screenshot: native shutdown reports `script_bindings.is_empty()` and exits `0xC000001D`. Original/candidate control pairs subsequently pass, so the intermittent engine failure's exact cause is unconfirmed. The retained static screenshot gameplay binding is an independently verified lifetime defect. `CaptureClock` now clears only the binding it owns on tree exit, and successful M6 captures queue/free the fixture and drain rendered frames/native audio before quitting, without forced collection. Eight subsequent full-clear captures pass strict native checks with the original image hash `58f44c2ddb6be7b0665fb2b8346ee052bd95e9aa58c8ccf98cd5b2be8b42a0b5`.

The new ownership regression initially created two unparented gameplay nodes. GdUnit reported two orphan nodes despite passing counters; that failed test version remains archived. Parenting those nodes to the auto-freed test scene fixes the test lifetime. The corrected test passes headless, Vulkan and Compatibility with no orphan diagnostics (`capture-binding-owned-*`). No native warning/error is allowlisted, and a repeat failure must still fail the full gate.

## Durable gate in the candidate

`tools/AotChecks/Dungeons.AotChecks.csproj` links the production host persistence/graphics contracts and references portable Core, without a Godot assembly. Its JSON reflection default is false. `tools/Test-AotCompatibility.ps1 -EvidenceDirectory <new-directory> [-Native]` also analyzes the actual shipping Game subset, and checks the existing full-clear development recording. That compatibility anchor is **not** promoted to a reviewed gameplay golden. Run `Test-Core.ps1` first to generate its development fixtures, or supply `-ReplayFile`.

The candidate's M8 runner invokes reflection-disabled checks; Linux/Windows CI and the Mac handoff request an actual native executable. Those hosted runs remain unexecuted. The local Windows result does not prove iOS arm64 linking, generated framework minimum-version metadata, Metal rendering or device execution.

Source generation and disabling reflection are described in [Microsoft's System.Text.Json guidance](https://learn.microsoft.com/en-us/dotnet/standard/serialization/system-text-json/source-generation). The Roslyn connector is unavailable in this session; authoritative compiler/analyzer output, emitted generator files, full tests and actual native execution provide the local evidence instead.
