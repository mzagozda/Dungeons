## Canonical authoring serialization

`LevelSerializer.Write(LevelDocument)` returns JSON with ordinally sorted object keys at every depth, original array order, two-space indentation, normalized exact decimal numbers, LF line endings and one final LF. Unicode and unknown forward-compatible fields survive reload/write. The API does not mutate the bound document, its cached exact source hash or runtime state. Code-only scenarios have an explicit error because they do not carry an authored package source; null documents have an argument error.

Number normalization operates on decimal digits rather than converting through binary floating point or the bounded Decimal type. It preserves integers above 2^53, arbitrary precision fractions, underflow-sized values and exponents outside Int64. Common magnitudes use fixed notation, with scientific notation below 1e-6 or at/above 1e21. Exponent carry/borrow is linear in digit count. This remains portable BCL/JSON code on both Core targets; no engine or extra runtime dependency is introduced. Existing runtime/content hashing and serialization are unchanged, so no replay candidate or shipped content file is rewritten by this addition.

Twenty serializer cases pass, including fifteen numeric edge cases, byte-identical canonical reload/write, original source/hash preservation, reversed key insertion order, pl-PL culture, array order, nested metadata/Unicode and explicit invalid-document errors. A generated-value case compares 2,000 decimal tokens against an independent exact BigInteger oracle in the test assembly and verifies valid JSON plus idempotence. The first focused run caught an exponent carry defect and Windows-specific writer newlines; both are fixed. Its diagnostic assertion was also corrected to allow informational default-application messages while still rejecting warnings/errors for the built-in level. ## Reversible command API — 2026-10-27

`Dungeons.Core.Level.Commands` provides ILevelCommand.Apply/Undo and SetTile, SetHeight, SetOverlay, SetCellProps, Resize, AddEntity, RemoveEntity, MoveEntity, SetEntityProps, AddTrigger, EditTrigger, SetObjective, SetEnvironment and SetMetadata. Entity/trigger selectors support unique authored ids and array indices for anonymous/duplicate-id repair. EditTrigger/SetObjective accept null to remove; SetEnvironment accepts null to restore defaults. Metadata edits preserve unrelated/unknown fields and can update flags/completion; structural collections use their dedicated commands. Input JSON is copied. The authoring API is intended for a single writer; game sessions retain independent baked snapshots.

LevelCommandBatch copies new child operations into one atomic brush/macro operation and binds/validates once. SetTile preserves height while clearing the previous overlay and cell override; SetHeight preserves the other cell attributes. SetOverlay can remove an overlay embedded in a composite palette reference, without leaving a hidden decoration. Shared palette entries are reused deterministically in ordinal symbol order, including equivalent plain/empty-object references. Property overrides remain per cell rather than changing a shared palette entry. No-op commands keep the document revision and exact-source identity.

A successful effective commit updates the same LevelDocument instance: raw authored source, dimensions/id, baked cells, the existing read-only placement-list view, resolved environment, content/source identities, mission cache, diagnostics and revision. Undo/redo restore those derived views as well as source. Normal LevelLoader.Load still returns no document on errors. LoadForEditing can retain structurally valid sources with semantic errors, allowing a missing reference or out-of-bounds placement to be repaired. GameSession construction/Create refuse a document reporting editing errors. Legacy PaintCell/AddEntity helpers also refresh binding/diagnostics after a document enters the command editing path. Structural failures leave source, caches, identities, revision and command history unchanged.

Resize uses nine named anchors; centre offsets round toward north-west for odd differences. It translates entities, trigger areas and cell overrides with the preserved grid. Cropped cell data is retained by undo. Entities outside the resized map remain in source and receive the usual placement diagnostics. Trigger areas are also retained without silently clipping authored logic; the existing v1 area-validation rules remain unchanged. Authored camera bounds translate and clip to the new map; an empty intersection restores default bounds. New cells use height zero and an explicit fill reference or a deterministic existing walkable, non-stair palette entry.

LevelCommandSerializer writes versioned LF JSON with stable key order, operation parameters, applied/undone state and compact reversible changes. Same-length arrays use changed values; insertions/removals retain only their changed middle splice. A ten-cell same-row brush records one row and one palette addition, while an appended entity retains only that entity. Canonical before/after SHA256 fingerprints and the content identity reject stale/out-of-order/wrong-document history; applying deltas to a temporary source and checking the resulting fingerprint prevents tampered history from mutating the live document. Canonical number comparison permits undo after saving/reloading canonical JSON. Exact original source identities are restored by undo. Unknown fields/types/versions, duplicate keys and malformed paths/changes are rejected. Macros support eight nested batch levels and up to 65,536 leaf edits. History has a separate 256 MiB/64-depth boundary because its operation and before/after data can exceed one level's 64 MiB; normal content/level parsing retains its original 64 MiB/32-depth limits.
