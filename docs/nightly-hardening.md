# Nightly hardening

`.github/workflows/nightly.yml` schedules the existing ten-minute data-fuzz gate, simulation fuzzing, rendered regression and a separate per-runner benchmark regression job. There is no Git remote or hosted run yet, so workflow configuration is not hosted acceptance. The required five green nights, hosted baseline measurements, iOS export and platform soaks remain pending.

The [simulation fuzz gate](simulation-fuzz.md) publishes isolated binaries, archives content and exact generated maps/inputs, and checks 32 cases for 10,000 actual ticks twice. Every tick checks finite transforms, bounds, collision penetration, living HP and deterministic hashes. Nightly seeds vary by UTC date and remain recorded for reproduction. The complete M8 runner also executes the default suite. This is distinct from wall-clock soak testing.

The rendered job installs pinned Godot/.NET/Python dependencies, starts Xvfb and selects the Compatibility renderer with Mesa software rendering (`LIBGL_ALWAYS_SOFTWARE=true`, `GALLIUM_DRIVER=llvmpipe`). Godot 4.4's Compatibility backend requires [OpenGL 3.3](https://docs.godotengine.org/en/4.4/about/system_requirements.html); the software selection follows [Mesa's documented environment variables](https://docs.mesa3d.org/envvars.html). This is a separate desktop review profile, not a reference-device performance measurement. Its first Linux run and baseline review remain pending.

`tools/Test-NightlyRendered.ps1` restores locked dependencies, builds current sources, regenerates/verifies the development completion replay, strictly imports resources, runs the complete GdUnit suite against the selected real renderer, executes the short native soak-scene diagnostic, repeats all 22 named captures and prepares an unreviewed candidate/contact sheet. The short diagnostic requires replay/results/catalogue/ordinary-recording coverage and cannot claim two-hour acceptance. It then compares against `assets/baselines/visual/<profile>/`. Missing review fails the job after the review artifacts are saved. There is no automatic approval, skipped baseline success, or replacement of expected files. Test logs, TRX, images, hashes, comparison diagnostics and an aggregate result are uploaded even when the gate fails.

```powershell
# From a desktop with the pinned toolchain and a real graphics display:
./tools/Test-NightlyRendered.ps1 -Profile windows-gl-rtx3060
./tools/Test-NightlyRendered.ps1 -Profile windows-mobile-rtx3060 -Renderer mobile
# For an already reviewed profile stored elsewhere:
./tools/Test-NightlyRendered.ps1 -Profile my-reviewed-profile -BaselineDirectory C:/Reviewed/my-reviewed-profile
```

Evidence directories must be new. The tool leaves all review and capture inputs read-only. Its aggregate result distinguishes rendered integration, named scenarios, candidate preparation and reviewed-baseline comparison. `physicalAcceptance` is always false. A missing/pending reviewed baseline intentionally makes the final command fail; preceding successful stages remain visible in the result and their logs.

The workflow's software renderer does not replace Mobile/Vulkan coverage, GPU budgets, physical Android/iOS checks or audio listening. Those remain separately tracked in the specification. The separate [performance job](performance-baselines.md) executes all six required BenchmarkDotNet fixtures, full Core/allocation/path-service/coverage checks and a fixed >20% regression gate. Missing runner references fail after preserving the candidate; Windows measurements never stand in for an unmeasured Linux runner.
