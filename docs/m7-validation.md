## Touch behavior

`TouchLayout` supplies the shared dp hit geometry and drawing geometry: floating joystick radius 60/dead zone 20/follow distance 90 dp; Attack/Roll/Bow/Potion diameters 84/64/64/56 dp with at least 12 dp gaps. Bounds respect supplied safe insets, the layout can mirror, and individual normalized button positions can be set for the later settings editor. `TouchState` keeps ten reusable pointer slots, independent movement/action capture, tap-only buttons, slide-off cancellation, OS cancellation and cleared state on pause/layout changes. A border tap produces no motion despite clamping the visible joystick inside the safe area.

Bow tap fires with auto-aim. Holding beyond 120 ms or dragging beyond 16 dp enters manual aim; releasing beyond the 12 dp dead zone fires, while returning inside cancels. Joystick movement continues during aiming. Actions are committed on a valid release so slide-off cancellation can discard a pending tap. The host projects screen input through the same camera basis as keyboard/gamepad movement. The command latch keeps manual aim together with the release edge until the next simulation tick, even if several 240 Hz samples intervene.

Eight touch cases and the existing latch case pass: `artifacts/m7/touch/mzag_R5-7600X_2026-10-26_20_36_48.trx`. They cover analog range/following, world taps, simultaneous fingers, duplicate capture, slide-off/cancel, bow tap/drag/hold/cancel, aim retention and mirrored phone/tablet bounds/spacing.

## Godot and native rendering

`TouchControls` handles screen-touch/drag events, draws original icons, cooldown/ammo feedback, joystick and a projected bow arrow, and adds touch pause. HUD margins use the same safe insets while reserving the pause area only from the top counter. Emulated mouse events cannot switch the active scheme or cause a second touch attack. Native screen scale converts physical pixels to dp; viewport/canvas transforms convert event positions and drawing positions consistently. System Back is routed through gameplay pause or menu back/quit confirmation, and screen-on follows active gameplay. ## Adaptive resolution and graphics profiles

`AdaptiveResolutionModel` uses a reusable 60-frame window, 0.05 steps down after a slow window (>18 ms), 300 consecutive good frames before stepping up, and a 0.6 floor bounded by the selected preset. After ten minutes of active measurement, an average over 20% above the initial baseline permanently lowers the threshold to 16 ms for that process. Pause/loading reset the current sample window while preserving active-time/thermal history across levels. Eighteen pure policy cases pass, including zero-allocation sampling, exact frame boundaries, limits, malformed profiles, ordered case-insensitive wildcard rules and preserved relaunch arguments: `artifacts/m7/graphics-policy/mzag_R5-7600X_2026-10-26_21_06_33.trx`.

`GraphicsRuntime` owns the shared model and applies scale only to the 3D buffer, with native canvas size unchanged. Low disables shadows/glow, selects 0.75 scale and four nearest lights; Medium/High use their specified shadow atlas and eight-light limit. Compatibility always uses Low. The bounded `content/device_profiles.json` table selects conservative policy rules; entries are not claims of device performance verification. The autoload logs its actual renderer/profile/rule. Two new real-engine cases verify binding, unchanged Core hashes/canvas dimensions and history across view replacement; all 21 Godot cases pass at `artifacts/m7/gdunit-graphics/mzag_R5-7600X_2026-10-26_21_14_03.trx`.

The Android Low export has the `android_low` feature, a preboot Compatibility project override and explicit launch flag (`tools/Export-M0.ps1 -Platform Android -Low`). Runtime forced-Compatibility rules use `OS.CreateInstance` before catalogue/profile IO. The pinned Android host replaces its process on this call; desktop starts a separate process. Neither the new Low APK nor automatic relaunch has yet been exercised on a physical device.

The real desktop relaunch probe first exposed a missing compiled QA class, then a functional issue: pinned `GetCmdlineArgs` contained only the remaining scene argument while user arguments were separate and engine audio flags had already been consumed. `FromGodot` now reconstructs the separator/user arguments and the runtime preserves the active audio backend explicitly. A first functional pass still exposed child WASAPI startup errors; it is rejected as clean evidence. Android startup defers renderer rebirth until the native import worker finishes its granted-URI copy, so pending files survive process replacement; that Android interaction still requires device validation.
